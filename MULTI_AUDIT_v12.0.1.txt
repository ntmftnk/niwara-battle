ニワラバトル v12.0.1 非シングル監査結果
========================================

対象
- ライブ: format-engine.js（ダブル / トリプル / 6vs6 / タッグ）
- 基準: game.js（詳細シングル）と game-data.js
- 研究: sim-core.js（高速ヘッドレスモデル）

実施した確認

[画面遷移]
- 初期表示: builder-screenのみ
- 編成 -> 対戦設定: mode-screenのみ
- シングル: selection-screenのみ
- ダブル/トリプル/6vs6/タッグ: format-battle-screenのみ
- 各形式からヘッダー「編成へ戻る」: builder-screenのみ
- タッグ4人全員humanで A1 -> A2 -> B1 -> B2 の選出と端末受け渡しを完走
- 上記でJavaScript例外 0

[ライブ技ランタイム]
- game-data.js の技 350種を、ダブル/トリプルそれぞれで applyMove() に全件投入
- ダブル: 350 / 350 実行、例外 0
- トリプル: 350 / 350 実行、例外 0

[データフラグ静的監査]
- 技の効果/挙動プロパティ: 150種類
- format-engine.jsで実処理または判定に接続: 147
- bite / bullet / pulse の3つは現行データでは分類タグのみで、基準シングルにも対応特性・持ち物による利用処理がないため挙動差なし
- 現行25種が持つ特性ID 54種: format-engine.js内で全IDを確認
- ITEM_DEX 70件: format-engine.js内で全IDを確認

[特性/持ち物ランタイム]
- 全特性を攻撃側/防御側へ差し替え、登場・攻撃・ターン末処理を実行: 例外 0
- 全持ち物を攻撃側/防御側へ差し替え、登場・攻撃・ターン末処理を実行: 例外 0

[CPU実戦スモーク]
- CPU vs CPUでダブル/トリプル/6vs6/タッグを勝敗決着まで実行
- 交代、ひんし交代、複数対象、ターン末処理を含めJavaScript例外 0

[ねばねばネット個別テスト]
確認済み:
- 通常の接地ポケモン: S -1
- あつぞこブーツ: 無効
- ひこう: 無効
- クリアボディ: 能力低下を防止
- かちき: S -1後にC +2
- マジックガード: S低下は発生
- どくタイプ+あつぞこブーツ: どくびしを吸収
- ねをはる中のひこうタイプ: 接地扱いでS -1

[研究コア]
- 5形式を各50戦実行し、各形式50戦の結果を完走
- NaN / Infinityなし
- ねばねばネット、あつぞこブーツ、どくびし吸収、クリアボディ系、かちき、こうそくスピン/きりばらいの基本処理を補正

重要な境界
- format-engine.js はライブ非シングルの実戦エンジンとして、game-data.jsの現在の技/特性/持ち物を横断監査した。
- sim-core.js は設計資料どおり「大量CPU自己対戦向け高速モデル」であり、ライブエンジンの全特殊効果を完全再現する設計ではない。
  今回は設置技を中心に不整合を補正したが、研究数値をライブ戦闘の完全再現値とは扱わないこと。
- ランタイム全件通過は「例外がない」こととデータフラグの接続を確認するもので、350技×全特性×全持ち物×全組合せの公式仕様完全証明ではない。
