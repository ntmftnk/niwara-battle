ニワラバトル v13.0.9 修正パッチ
================================
更新元: v13.0.8
PWA Service Worker generation: 25

目的
----
v13.0.6/v13.0.8系の研究AIでは、実戦結果に基づく対策型評価を導入した結果、
直前の世代への過剰反応は弱まった一方、種族採用がほとんど変わらない環境が見られました。
今回は通常の環境採用率を意図的に平坦化せず、有望な未検証構築を試し続けられるようにします。

変更内容
--------
1. 通常の研究試合20戦ごとに、独立した探索用対戦を1戦追加
   - 探索用対戦は実際に対戦エンジンで解決します。
   - 既存の通常構築の1枠を、新しい対策・低採用・実績不足の候補に入れ替えます。
   - 探索候補は選出段階で必ず選出します。
   - 片方の陣営だけを探索側とし、A/Bを交互に入れ替えます。
   - 相手は通常の研究AIの構築です。
   - 「完全ランダム寄り」構築では探索対戦を行いません。
   - 探索の追加実行分だけ計算負荷が増えます（標準で試合数ベース約5%）。

2. 探索用と通常研究の統計を厳密に分離
   - 探索戦は研究の目標試合数・通常の種族使用率・選出率・勝率・対面記録に加算しません。
   - 探索の試合数・候補側勝敗は exploration に記録します。
   - 候補種族（species）、種族+特性（variants）、探索側で同時選出した仲間とのペア（pairs）を記録します。
   - 対戦チームとしての勝敗であり、1対1の対面勝率ではありません。
   - 詳細な結果はCSV / JSONの累積データと区間スナップショットに保存されます。

3. 探索結果を次世代構築へフィードバック
   - 既存のEMA（最新世代45%）は維持します。
   - 探索結果の勝率にはベイズ平滑化とサンプル数依存の信頼度を適用します。
   - 高い実績の候補は本番構築の種族・特性・ペア評価に限定的に加点します。
   - 実績が悪い候補は減点します。
   - いずれも最大補正値を制限し、探索統計が基本の技・相性・実戦評価を上書きしないようにします。
   - 成果がなければ特定の候補の本番採用を強制することはありません。

4. 研究画面
   - 「探索用対戦（別枠）」「探索側の勝率」をサマリーに追加。
   - CSVのセクション名: exploration_summary / exploration_species / exploration_variants /
     exploration_pairs、および対応する snapshot_exploration_*。
   - 旧研究データは読み込み可。以前存在しなかった探索統計は0として扱います。

注意
----
- 実戦チームの構築強度は計測条件（乱数シード、CPU難易度、研究バージョン）にも依存します。
- 10万戦規模のメタ安定性が改善したかどうかは未検証です。
- 過去v13.0.8以前の研究に新しい探索実績を後付けすることはできません。
- 公平な比較のためv13.0.9で新規研究を開始してください。
- 探索用試合の勝率は「探索候補を選出したチームの勝率」であって、直接の1対1勝率ではありません。
